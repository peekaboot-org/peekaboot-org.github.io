Quick start GitHub

Peekaboot is beta software and may expose security-relevant settings. Use it at your own risk.

A local run keeps traces across restarts under ~/.peekaboot, with SQL, bind parameters and log lines unmasked. Set peekaboot.storage.traces.enabled=false to keep them in memory only. See Security, what goes to disk.

Add the dependency

Requires Java {{ site.java_version }} or newer, Spring Boot {{ site.spring_boot_version }} and a servlet web application.

Maven

<dependency>
    <groupId>{{ site.maven_group }}</groupId>
    <artifactId>{{ site.maven_artifact }}</artifactId>
    <version>{{ site.peekaboot_version }}</version>
</dependency>

Gradle

implementation("{{ site.maven_group }}:{{ site.maven_artifact }}:{{ site.peekaboot_version }}")

Dashboard

Health, build and Git info, environment, configuration properties, Flyway and Liquibase migrations, logger levels and scheduled tasks, at /peekaboot in your running app. Lifecycle lists every run of the app, Meters every meter in its registry. The dashboard

Traces with SQL queries

The last 1,000 requests your app served, with no collector to run, each with its span tree, SQL queries and timings. On a local run they survive a restart. With context propagation on, work your @Async methods run shows up inside the request that started it. Errors and slow requests are kept in buckets of their own. Traces

Charts of CPU, memory, HTTP, connection pool and JDBC query metrics over time, from the meters your app already publishes. Insights

HTTP API for agents and scripts

What the dashboard shows is JSON under /peekaboot/api, with Peekaboot's own verdicts, such as a trace's cause, the routes that fail and the error digest. A log search covers every line the store holds. GET /peekaboot/api lists every endpoint and links the OpenAPI 3.1 document. An agent starts from llms.txt or the peekaboot skill. HTTP API covers every field, Agents has the recipes. 

curl -s http://localhost:8080/peekaboot/api | jq
curl -s http://localhost:8080/peekaboot/api/routes | jq
curl -s http://localhost:8080/peekaboot/api/errors | jq

Off on a deployment

Peekaboot is on when you start your app from the IDE, with spring-boot:run or with bootRun, and off for a deployment or a test unless you turn it on. Do I want this in production? covers what it costs while it is on and how to keep it out of the artifact.

Why Peekaboot?

Peek, because it lets you look inside a running application. Boot, because that's where it lives. And peek-a-boo, because that's how it behaves. Add one dependency and your app's internals show up on a local run, where only your own machine can read them. Deploy the same jar and Peekaboot stays off. What the starter still brings stays on the classpath.

Peekaboot builds on ideas from Symfony's profiler, Spring Boot Admin and others. See the acknowledgements.
