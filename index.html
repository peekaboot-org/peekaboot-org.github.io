Peekaboot

{{ site.tagline }}

Add one dependency, run your app, and a dev toolbar appears on every page — request and response detail, the trace view, and logs correlated to the request, right on the page you're already looking at. A local dashboard comes with it: health, config, environment, live metric charts, Flyway migrations, and the last thousand traces your app has served. Everything lives in memory inside your own process: no collector, no agent, no external service — and both default to off outside local development.

Quick start GitHub

Add the dependency

One starter. Nothing else to install or run.

Maven

<dependency>
    <groupId>org.peekaboot</groupId>
    <artifactId>peekaboot-spring-boot-starter</artifactId>
    <version>{{ site.peekaboot_version }}</version>
</dependency>

Gradle

implementation("org.peekaboot:peekaboot-spring-boot-starter:{{ site.peekaboot_version }}")

On the page you're testing

The dev toolbar docks to the bottom of every page your app renders locally, on by default: request and response detail, the trace view — span tree, timings, queries — and every log line the request produced, correlated with no grep. It works from Swagger UI too.

A dashboard, too

The same toolbar links to a full dashboard: health, config, environment, charts of CPU, memory, HTTP and pool metrics over time, Flyway migrations, and the last thousand traces your app has served — kept for thirty minutes — not just the one on your screen.

No infrastructure

Traces, config and everything else live in an in-memory store inside your own process. No collector, no agent, nothing to stand up before you can see the first request.

Off in production by default

Both the toolbar and the dashboard key off the same local-launch detection — an IDE run or spring-boot:run/bootRun — and default off for every packaged jar, container, and test run.

Add it, run your app, the toolbar is on the page.
