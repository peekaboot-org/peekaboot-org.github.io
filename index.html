Dev toolbar

A bar at the bottom of every HTML page your app renders. Click it for request and response detail, the span tree with timings and queries, and the log lines of that request. It also works in Swagger UI. Dev toolbar

Dashboard

Health, build and Git info, environment, configuration properties, Flyway and Liquibase migrations, logger levels and scheduled tasks, at /peekaboot in your running app. The dashboard

Traces with SQL queries

The last 1000 requests your app served, held in memory with no collector to run, each with its span tree, SQL queries and timings. With context propagation on, work your @Async methods run shows up inside the request that started it. Errors and slow requests are kept in buckets of their own. Traces

Insights

Charts of CPU, memory, HTTP, connection pool and JDBC query metrics over time, from the meters your app already publishes. Insights

Off on a deployment

Peekaboot is on when you start your app from the IDE, with spring-boot:run or with bootRun, and off for a deployment or a test unless you turn it on. Do I want this in production? covers what it costs while it is on and how to keep it out of the artifact.

Why Peekaboot?

Peek, because it lets you look inside a running application. Boot, because that's where it lives. And peek-a-boo, because that's how it behaves. Add one dependency and your app's internals show up on a local run. Deploy the same jar and Peekaboot stays off.

Peekaboot builds on ideas from Symfony's profiler, Spring Boot Admin and others. See the acknowledgements.
