Add the dependency

Requires Java 25, Spring Boot 4.1 and a servlet web application.

Maven

<dependency>
    <groupId>{{ site.maven_group }}</groupId>
    <artifactId>{{ site.maven_artifact }}</artifactId>
    <version>{{ site.peekaboot_version }}</version>
</dependency>

Gradle

implementation("{{ site.maven_group }}:{{ site.maven_artifact }}:{{ site.peekaboot_version }}")

Dev toolbar

A bar at the bottom of every HTML page your app renders. Click it for request and response detail, the span tree with timings and queries, and the log lines of that request. It also works in Swagger UI. In place of Spring Boot's whitelabel page, errors show the stack trace with framework frames folded. Dev toolbar

Dashboard

Health, build and Git info, environment, configuration properties, Flyway migrations, logger levels and scheduled tasks, at /peekaboot in your running app. The dashboard

Traces with SQL queries

The last 1000 requests your app served, each with its span tree, SQL queries and timings. Errors and slow requests are kept in buckets of their own. Traces

Insights

Charts of CPU, memory, HTTP, connection pool and JDBC query metrics over time, from the meters your app already publishes. Insights

Off outside a local run

Peekaboot is active when you start your app from the IDE, with spring-boot:run or with bootRun. It stays off for java -jar, wars, native images, containers and tests, unless you turn it on explicitly. Do I want this in production? covers what it costs while it is on and how to keep it out of the artifact.

Why Peekaboot?

Peek, because that's what it does — a look inside a running application. Boot, because that's where it lives. And peek-a-boo, because that's how it behaves: add one dependency and your app's internals are suddenly there; package the jar and they're gone again.

In short: Peekaboot lets you peek inside your Spring Boot application while it runs.

Peekaboot builds on ideas from Symfony's profiler, Spring Boot Admin and others. See the acknowledgements.
