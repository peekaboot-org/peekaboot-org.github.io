Peekaboot

{{ site.tagline }}

Peekaboot adds a local dashboard to your Spring Boot app — health, config, environment, scheduled tasks, metrics, Flyway migrations, and full request traces with span trees, SQL queries and correlated logs. Everything lives in memory inside your own process: no collector, no agent, no external service — and it defaults to off outside local development.

Quick start GitHub

Add the dependency

One starter. Nothing else to install or run.

Maven

<dependency>
    <groupId>org.peekaboot</groupId>
    <artifactId>peekaboot-spring-boot-starter</artifactId>
    <version>{{ site.peekaboot_version }}</version>
</dependency>

Gradle

implementation("org.peekaboot:peekaboot-spring-boot-starter:{{ site.peekaboot_version }}")

See inside a request

Every request Peekaboot captures becomes a trace: the full span tree, the SQL each span ran, and the log lines emitted while it executed — correlated automatically, no manual instrumentation.

No infrastructure

Traces, config and everything else live in an in-memory store inside your own process. No collector, no agent, nothing to stand up before you can see the first request.

Off in production by default

peekaboot.enabled defaults to true only for a local launch — an IDE run or spring-boot:run/bootRun — and to false for every packaged jar, container, and test run.

Nothing new to expose

Peekaboot invokes Actuator's endpoints in-process and serves the result through its own API — it never needs management.endpoints.web.exposure.include, so nothing new becomes reachable over HTTP.

Add it, run your app, open the dashboard.
